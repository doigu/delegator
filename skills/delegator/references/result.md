# Result contract, version 10

Version 10 adds the optional `exec` `--result-file` for unattended runs, revisiting the R4/R11 no-delivery-protocol stance: the path must be outside every Git repository and must not exist — a rejected path is a `configuration_error` with the code `result_file_invalid` before any launch — and the final JSON result of the whole call (the aggregate after capacity retries and alias routing, equally a caught wrapper error) is written there atomically (a `<name>.tmp` sibling plus `os.replace`) before the stdout print, with the expanded path reported in `result_file`. A failed write is a `warnings` entry without a status change; a missing result file means the outcome is unknown and never authorizes a repeat by itself. `ask` has no `--result-file`: its contract is a plain-text answer. Version 9 tags the listed `configuration_error` payloads with a machine-readable `code` field (see "Configuration error codes"). Version 8 keeps the full answer: `answer` is the redacted answer capped at 2000 characters, `answer_truncated` reflects the post-redaction length, and when the redacted answer exceeds 2000 characters the full redacted answer is written to `answer_path` (next to the attempt's log, `<log-stem>.answer.txt`); `answer_length` carries the full redacted length, a failed file write is a `warnings` entry with `answer_path` null, and without `--json` `ask` prints the full answer from `answer_path`. Version 7 separates a worker question from native input failures: a `NEEDS_USER_INPUT` marker at the start of the terminal answer is `status` `needs_input` with `stop_reason` `worker_question` and CLI exit code 3, and the observed `session_id` is kept for `--resume-session`; a native input or permission failure without a terminal answer stays `failed`/`needs_user_input` with exit code 1. There is still one marker and no marker grammar. Version 6 adds the launch-environment canary: `exec`/`ask` probe user-profile writability before any launch, a blocked profile returns `configuration_error` with the calling environment named in `reason`, and an alias whose every route was skipped by such a blocked write reports the environment in `reason` instead of `No route of the alias was run`; OpenCode top-level `Error: <generic>` stderr failures carry the following cause line in `reason`. Version 5 added the one-shot `ask`/`test` commands without a repository (fresh temporary directory, review/shell `none`, no retries, plain-text `ask` output with the full JSON under `--json`) and the `test` per-model output shape. Version 4 added model aliases with ordered routes: `exec -m <alias>` runs a candidate chain with `attempt_routes`/`alias` result fields, per-route retries (`--route-retries`), and explicit alias error shapes. Version 3 added automatic wrapper retries for classified `capacity` failures with the `attempts`/`log_paths` result fields, and the `--shell none|auto|full` exec level; `requested` gains `shell` (the resolved level, after the agy `auto` degradation). Version 2 added the `denied_actions` result field and the classification of native permission denials. `exec` prints one JSON result on stdout; `ask` prints the answer as plain text unless `--json`; `test` prints per-model lines and a summary; progress goes to stderr. CLI argument errors are handled by argparse: stderr and exit code 2, without a JSON result. A completed native invocation still requires independent acceptance by the calling agent.

## Status, stop reason, and process exit code

| `status` | `stop_reason` | CLI exit code | Meaning |
|---|---|---:|---|
| `completed` | `completed` | 0 | Native turn finished with a nonempty answer and no classified failure; overcome permission denials are listed in `denied_actions` |
| `needs_input` | `worker_question` | 3 | Worker question: the final answer starts with `NEEDS_USER_INPUT`; not a failure, `session_id` is kept for `--resume-session` |
| `failed` | `quota`, `capacity`, `auth`, `native_error` | 1 | Classified native failure; `capacity` is retried by the wrapper (see below); only confirmed `quota` blocks the selected provider |
| `failed` | `needs_user_input` | 1 | Native input failure, or a permission denial without a terminal answer; this is not successful completion |
| `failed` | `native_exit_nonzero` | 1 | Native process exited unsuccessfully without a more specific classification |
| `failed` | `no_terminal_answer` | 1 | Missing terminal event or empty answer |
| `failed` | `output_limited` | 1 | Native output-length limit reached with a partial answer; narrow the scope before another attempt |
| `failed` | `reported_selection_mismatch` | 1 | Reported selection disagrees with the requested selection |
| `cancelled` | `cancelled` | 1 | Interrupted; native process tree is stopped, edits remain |
| `timed_out` | `max_runtime_exceeded` | 1 | Explicit runtime limit reached; native process tree is stopped, edits remain |
| `configuration_error` | absent | 2 | Configuration, input, launch, or another caught wrapper error; details are in `reason` |

A classified `capacity` stop reason is retried automatically by the wrapper: up to `--capacity-retries` extra native attempts (default 3; config `execution.capacity_retries`) with progressive backoff starting at `--capacity-retry-seconds` (default 30; config `execution.capacity_retry_seconds`) that doubles each retry; a retry notice goes to stderr and each retry decision lands in `warnings`. Capacity covers transient provider-side failures: harness capacity wordings plus generic server-error markers (`provider returned a server error`, `server_error`, `internal server error`, `service unavailable`, `bad gateway`, `gateway timeout`, `model is overloaded`, `network connection failed`); generic `429`/rate-limit text stays `native_error`. A retry resumes the failed attempt's observed `session_id` when there is one, otherwise it starts fresh with the same prompt; an interrupted wait returns the last failed result. `--max-runtime-seconds` remains a whole-call budget: a retry runs only on the unspent remainder, and no retry starts without one. With more than one attempt, `attempts` counts native launches, `log_paths` lists every attempt's full log (`log_path` is the last), `preexisting_changed_paths` comes from the first attempt, `usage` is summed across attempts, and `elapsed_seconds` covers the whole call including waits; `resumed` still reflects the explicit user request, not an internal retry resume. The last attempt's outcome is reported: exhausted retries end `failed`/`capacity`.

## Configuration error codes

The listed `configuration_error` payloads carry a `code` field:

| `code` | Site |
|---|---|
| `profile_not_writable` | The launch-environment probe could not write the user profile home |
| `model_not_selected` | No model address was given, or the given full address is missing or unavailable |
| `unknown_alias` | The alias is not defined in the registry (`exec`/`ask` and `test`) |
| `no_available_route` | Every route of the alias is unavailable at launch |
| `environment_blocked` | No route of the alias ran and a skip warning reports a blocked write |
| `no_route_ran` | No route of the alias ran for any other reason |
| `log_directory_inside_git` | Every candidate log directory lies inside a Git repository or is unusable |
| `result_file_invalid` | The `--result-file` path lies inside a Git repository or already exists |

`code` is present only on these configuration errors; its absence means an unclassified cause (other registry validation errors, reported through the generic exception handler, stay without `code`). Branch on `status` plus `code`; `reason` is human-readable text only.

## Alias routing

`exec -m <name>` without `/` resolves a registry alias to its ordered full-model routes and runs them in order. Routes unavailable at launch (disabled, quota-blocked, no executable module, or lacking an explicitly requested effort) are skipped with warnings; routes whose per-route preparation fails (native CLI not installed, a zcode model without an explicit or default effort) are also skipped with warnings. An explicit `--shell auto` for an agy route is a configuration error, as with a full address. `-e` selects the effort for every route and drops the routes that do not list it; without `-e` each route runs with its own `default_effort`.

A candidate gets up to `--route-retries` extra attempts (default 1; config `execution.route_retries`) after a classified `capacity` failure — the same resume-or-fresh retry and backoff mechanics as a full-address call. Exhausted capacity retries and a confirmed `quota` (which blocks the provider like a full-address call) hand off to the next route immediately, without a wait; remaining routes of the blocked provider are skipped with warnings. Any other stop reason (`failed`, `needs_user_input`, `worker_question`, `cancelled`, `timed_out`, `output_limited`, …) ends the chain with that attempt's result; there is no fallback for them. A hand-off to a different route always starts fresh with the same prompt — the worker sees the previous attempt's diff; warnings list the changed paths of the failed attempt. `--max-runtime-seconds` is the budget of the whole call: every route launch, including the first one after a hand-off, runs only on the unspent remainder. `--resume-session` is rejected with an alias; resume continues the reported attempt by its full address from `requested`. Explicit `--capacity-retries`/`--capacity-retry-seconds` are rejected with an alias, and `--route-retries` is rejected with a full address; the config keys of the opposite domain do not apply.

The result reports the last attempt's outcome with flat aggregation across all attempts: `attempts` counts every native launch of the chain, `log_paths` and `attempt_routes` are parallel lists (route address per attempt), `usage` is summed, `preexisting_changed_paths` comes from the first attempt, `elapsed_seconds` covers the whole call, and `warnings` merges chain diagnostics with the last attempt's. `alias` carries the requested alias name (absent for a full address), and `requested` reflects the actual final attempt (route address and its resolved shell), so the reported-selection check compares against that route.

Configuration errors return exit 2 with these shapes: an unknown alias returns `status`, `reason`, and `aliases` (the defined names); an alias without an available route returns `status`, `reason`, `alias`, and `routes` — each `{address, available, reason}`. When no route ran and a skip warning reports a blocked write (`not writable`), `reason` names the calling environment instead of `No route of the alias was run`; the per-route specifics stay in `warnings`.

`reason` is a human-readable diagnostic, possibly null; use `status` and `stop_reason` for branching. `NEEDS_USER_INPUT` at the beginning of the final answer is a worker question: `status` `needs_input`, `stop_reason` `worker_question`, exit code 3, and the observed `session_id` is kept so the lead may answer and continue with `--resume-session`. A marker with a terminal answer takes precedence over classified stderr failures (including `quota`) and over permission denials; a native input or permission failure without a terminal answer remains `failed`/`needs_user_input`. `NEEDS_LEAD_ADVICE` is not a marker. No complete marker grammar is parsed. A request for input does not authorize an automatic restart or model change. `output_limited` comes from a native terminal finish reason (`length`), not from answer or tool prose; it does not block the provider or authorize an automatic rerun. Antigravity reports a terminal `result` event with `status`, `usage`, and a conversation ID; a non-`SUCCESS` status becomes a native failure, and its native `denied_actions` list is kept in the result. Its conversation ID is reported as `session_id`; explicit resume passes it back as `--conversation`, and because a foreign or dead id silently starts a new conversation, the reported id is confirmed after the run (`resume_session_mismatch`). Claude Code reports its selection in the `system/init` event (mid-turn message models are ignored, so an alias request can end in `reported_selection_mismatch`); its terminal `result` event finishes only on `subtype == success` without `is_error`, `error_max_turns` is an ordinary native failure, a `rate_limit_event` is advisory and ignored, and `usage`/`cost` come only from the native `usage`/`total_cost_usd` fields. Its session ID is a UUID confirmed on explicit resume.

## One-shot commands: `ask` and `test`

`ask` is one prompt through the same runner and result contract as `exec`, with fixed semantics: no `--repo` (the worker runs in a fresh temporary directory outside Git, removed after the run, including on failure; the Codex native Git working-copy check is waived for the throwaway directory — `--skip-git-repo-check`, sandbox level untouched), review mode with shell `none`, no `--mode`/`--shell`/`--resume-session`/`--prompt-file`, and no wrapper retries — a full model address runs exactly once (`capacity` is terminal, no backoff), and an alias runs each route once, handing off to the next route on `capacity`/`quota` without a wait. Selection, quota blocking, the reported-selection check, and exit codes are unchanged (a worker question exits 3). A missing/empty prompt or an unusable selection is a `configuration_error` like `exec`. Without `--json`, `ask` prints the full answer as plain text on stdout (when the answer was truncated, it is read from `answer_path`; an unreadable file prints a note to stderr) and, for any outcome other than `completed` or `needs_input`, a one-line `ask failed: <stop_reason>: <reason>` note on stderr (a selection error also lists `available: <address>` lines); a worker question is printed as the answer, with no `ask failed` line. `--json` prints the full runner result with `changed_paths`/`preexisting_changed_paths` empty (`[]`).

`test` checks configured models. Without `-m` it addresses every available model; with `-m` one full address or every route of an alias (an explicitly named unavailable model is reported as an offline failure with its reason, without a request). Each address gets an offline validation — registry availability, native CLI resolution, and launch preparation through the harness adapter (a missing ZCode plan key or an unconfigured effort fails here) — then one live `ask` turn with the fixed prompt `Reply with exactly the word: Hi` at the model's default effort (or `-e`; an effort the model does not list is an offline failure). Text output is one `address | ok|fail | detail` line per model plus a final `passed X/Y`; `--json` prints one entry object per line and then `{command, passed, total}`. Each entry is `{address, phase: offline | live, ok, status, stop_reason, reason, answer, log_path, elapsed_seconds}`; for an offline failure `status` is null and `reason` carries the check's message. Exit code `0` only when every tested model is `ok`, `1` when any failed, `2` for configuration errors (an unknown alias prints the `configuration_error` JSON). A live `quota`/`capacity`/`auth` failure is that model's `fail` with its classified fields, and a confirmed live `quota` blocks the provider in the registry exactly like `exec`.

## Result shapes

The normal runner result has these fields:

| Field | Meaning |
|---|---|
| `status`, `stop_reason`, `reason` | Outcome, machine-readable stop reason, and diagnostic |
| `answer`, `answer_truncated`, `answer_length` | Redacted answer capped at 2000 characters; explicit truncation flag based on the post-redaction length; full redacted answer length |
| `answer_path` | With truncation: full redacted answer saved next to the attempt's log as `<log-stem>.answer.txt`; null when the answer is not truncated or the file could not be written (a write failure is a `warnings` entry) |
| `requested` | Explicit `harness`, `provider`, `model`, selected `effort`, and resolved `shell` level; absent effort is null; with an alias these describe the actual final attempt |
| `alias` | The requested alias name for an alias call; absent for a full address |
| `reported` | Native `harness`, `provider`, `model`, and `effort`; each unknown value stays null |
| `changed_paths` | Paths in ordinary Git status after execution; includes preexisting changes |
| `preexisting_changed_paths` | Paths in ordinary Git status before execution |
| `log_path` | Full redacted native stdout/stderr log outside Git; the wrapper inherits the calling environment, and if the system TEMP/TMP falls inside Git the log goes to a permanent local user directory (`%LOCALAPPDATA%\delegator` or the XDG state directory) that is never cleaned automatically — override with `--log-dir` |
| `result_file` | With `exec --result-file`: expanded path the final result was written to, atomically before stdout; a failed write is a `warnings` entry and the outcome is unchanged; absent without the flag |
| `attempts`, `log_paths` | Number of native launches including capacity/route retries (1 when none), and each attempt's full log path; `log_path` equals the last entry |
| `attempt_routes` | With an alias: the route address of every attempt, parallel to `log_paths`; absent for a full address |
| `session_id` | Native session ID if observed, otherwise null, including on native failure |
| `usage` | Native numeric usage fields, or null if none observed; schemas differ by harness |
| `elapsed_seconds`, `native_exit_code` | Wrapper elapsed time for the whole call (capacity-retry waits included) and the native process code; code is null if no worker was started |
| `warnings` | Nonfatal log, parsing, or quota-persistence diagnostics |
| `quota_reset_at` | Reset time inferred from a classified native quota error, otherwise null |
| `denied_actions` | Native permission denials observed during the run, each `{tool, detail}` (`tool` may be null, `detail` is redacted and capped at 300 characters); at most 20 entries; empty list if none |

A missing or unavailable model returns the shorter shape `status`, `reason`, `available_models` with exit code 2. Each listed model has `address`, `efforts`, and `default_effort`. Alias errors are described in "Alias routing" above. A caught wrapper exception returns `status`, `config`, and `reason` with exit code 2. These error shapes need not contain runner fields; a configuration error alone does not prove that no partial work occurred. Management commands have their own JSON shapes: `list` returns `config` and `nodes`; mutations return `command`, `addresses`, `dry_run`, `quota_cleared`, and `warnings`; `alias list` returns `command` and `aliases`; `delete`/`sync --prune` warn when an alias still references a deleted address.

## Interpretation and limits

- Permission denials come from native signals only: OpenCode tool errors that mention permission, approval, or rejection; the Antigravity terminal `result.denied_actions`; the Claude Code terminal `result.permission_denials`; Codex `Rejected(... rejected: <reason>)` router lines on stderr (a command the sandbox policy refused to run, for example an escalation with no approver); ZCode `interaction/requestPermission` requests, which Delegator declines. A filesystem error inside a command Codex did run (for example `Access is denied`) is indistinguishable from an ordinary failure and is not listed. A declined ZCode `interaction/requestUserInput` still ends the run with `needs_user_input`. OpenCode auto-rejects an `ask` headless and ends the turn, so the adapter keeps `none`/`auto` to `allow`/`deny` and a denied tool is hidden from the model's tool list (live check 2026-10-27). A denial is not a failure by itself: when the native terminal is reached with a nonempty answer, the run is `completed` with the denials listed, unless the answer is a worker question, which is `needs_input`; otherwise it is `failed`/`needs_user_input` with `reason` `Native tool permission denied`. Earlier classified failures (`quota`, `native_exit_nonzero`, `output_limited`, and so on) take precedence over denials; a worker-question marker in a terminal answer still wins. A listed denial can mean that a requested step, such as a check, was skipped; the answer and diff must show what was actually done.
- Absence of reported metadata is uncertainty, not confirmation or a mismatch. Requested values are never substituted for missing reported values. When a reported value exists and disagrees, `exec` fails. Read `reported` per field: `harness` is null today because no adapter reports it; `model`, `provider`, and `effort` are filled only when the harness supplies them (ZCode via `session/read`, OpenCode via info events, Claude Code via `system/init`, Codex via metadata, Antigravity via `init`) and stay null otherwise. A partially filled `reported` means exactly that: the filled fields are confirmed, the rest are unknown. Native metadata confirms the client's selection, not the backend that actually served the request. For example, a filled `requested.model` with a null `reported.model` means the model was requested without native confirmation — neither a confirmed model nor an error.
- Inspect the actual Git diff and substantive checks, especially after cancellation, timeout, or failure. Comparing path lists alone cannot detect further edits to a path that was already dirty. No rollback is performed and no `partial_changes` field is inferred.
- A failed log/status write must not stop useful work. Log failures are returned in `warnings` when a result can be returned. Beyond stdout, `exec --result-file` is the only durable delivery path (see version 10); a lost host handle or unavailable stdout must not be interpreted as completion — check the result file, the session, the log, and the working tree before any repeat.
- Redaction covers known secret formats; it cannot guarantee removal of every secret from arbitrary native output. Keep logs local and avoid placing credentials in prompts.
- `list` reports each node's own `enabled`, effective `available`, and an explanatory `reason` when unavailable. Effective model availability checks ancestor flags, provider quota, and supported executable modules; it does not probe CLI installation, credentials, server access, or capacity.
- For `on`, `quota_cleared` lists providers whose quota block was cleared across the selected scope; descendant `enabled` flags are unchanged. `list/on/off/delete` are offline. `add` checks the native catalog when available: Codex uses its local cache, OpenCode invokes `opencode models <provider>`, Antigravity invokes `agy models`, and ZCode is checked against the installed builtin table (plan provider, model, and efforts; `ZCODE_BUILTIN_PROVIDER_CONFIG_FILE`, else install paths). Claude Code has no local model catalog: `add` records the full model id without verification. Missing/unreadable catalogs produce warnings where handled; a model absent from a successfully read catalog is rejected. This is not a live guarantee that the provider will serve the model, and `add` is not guaranteed to be offline.
- Native configuration, including MCP, is inherited. Delegator adds no MCP isolation; the selected harness's native sandbox and permissions govern tool access.
- ZCode reports its selection through `session/read`, not through a turn event. A missing model report fails the run; a different reported model is `reported_selection_mismatch`. `reported.effort` is filled only when the native session reports a reasoning level.
- The ZCode session mode follows `--shell` (`plan`/`edit` for `none`, `guarded` for `auto`, `yolo` for `full`); only `yolo` is unprotected. In the other modes the boundary is the native mode plus the assignment `SCOPE`. `changed_paths` (and the lead's before/after HEAD check) are the evidence; existing paths can hide further edits, and a worker commit leaves `changed_paths` empty.
- ZCode quota is recognized only from explicit Zhipu `1301` markers on a failed turn or backend error. Generic `429`, `RESOURCE_EXHAUSTED`, and successful-turn prose do not block the provider. ZCode has no output-length signal; `output_limited` is not inferred. Explicit resume calls `session/resume` with the `sess_<UUID>` id; a foreign or dead id is `resume_session_unconfirmed` (the native refusal text stays in `reason` and does not block the provider), a mismatched native echo is `resume_session_mismatch`, and the answer never comes from the resumed transcript.
- A ZCode Coding Plan key may be stored encrypted; the adapter decrypts it in memory with a Node helper. The key is not returned, logged, or stored in the registry.
- Claude Code pins `--permission-prompts none` only at `--shell none`. At `auto`/`full` the flag is dropped and the native classifier decides (`plan`/`acceptEdits` for `none`, `auto` for `auto`, `bypassPermissions` for `full`): plainly safe commands run without a prompt, risky shapes are denied headless and land in `denied_actions`; pinning the flag at `auto` denies even safe commands (live check 2026-10-24). Native settings, MCP, and hooks are inherited without isolation. Claude quota is recognized only from the explicit native `Claude AI usage limit reached` stderr line; the trailing epoch is not parsed, so `quota_reset_at` stays null while the provider is blocked. Generic `429`/`rate limit` text, answer prose, and tool output do not block the provider.
